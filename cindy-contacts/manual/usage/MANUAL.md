# 用通讯录记人与整理

通讯录只保存在用户本机。你读到的档案会进入当前对话，由用户配置的模型处理。

## 先查再写

1. 对话里出现一个人或组织——陌生邮箱、手机号、平台 id、"这是谁"、要给某人发消息、准备会议——先调用
   `ghost_call({ ghost_id: "cindy-contacts", tool: "find", args: { query: "<线索原文>" } })`。
2. 命中后用 `get` 读全量档案，再决定是更新还是什么都不做。不要凭记忆新建。
3. `save` 新建返回 `DUPLICATE_SUSPECT` 时，逐个 `get` 候选确认是不是同一人：是，就带 `id` 更新；不是，才传 `allow_duplicate: true`。
4. 返回 `IDENTITY_CONFLICT` 时，这个邮箱/账号已属于 `conflictContactId` 那个人：更新那份档案，或确认是同一人后 `merge`。

## 什么值得记

- 值得记：与用户真实共事或生活的人，以及持久的事实——新联系人、职位/公司/团队变化、新联系方式、明确的约定、值得记住的一次往来。
- 不记：一次性发件人、营销邮件、通知机器人、群发通讯；对话里顺带提到但与用户无关的名人。
- 推断出来、没有直接依据的信息（猜测的职位、关系）不写成事实；写进 narrative 时说明依据，或者不写。

## 怎么写

- `summary` 是一句话介绍：是谁、在哪、做什么。
- `narrative` 是长期背景和你们的故事，用自然语言写几句；它会被整体覆盖，修改前先 `get` 读出原文再改写，不要丢掉旧内容。
- 有时效的事实用 `log_event` 记成带日期的事件（`date` 用事情发生的日期，不是今天）。
- `agent_notes` 只写给 AI 的处置提示，如偏好的联系方式、称呼、注意事项。
- 平台名用小写：`email`、`phone`、`feishu`、`slack`、`github`、`wechat`、`telegram`、`x`。

## 合并、删除与导入

- 合并：有把握就直接 `merge`，并在 `reason` 写一句依据。有把握指同一个邮箱、手机号或平台账号；或同名且公司、上下文一致。合并会留下记录，用户可以在资料页「拆开」。拿不准就不合并。
- 删除：只在用户明确要求时 `delete`，传 `confirm: true`。`groups` 的 `delete` 和 `organize` 的批量移动同样要用户明确要求。
- `import_macos` 先用默认的 `dry_run` 告诉用户会新建和补全多少人，用户同意后再传 `dry_run: false`。

## 整理通讯录

1. `find_duplicates` 找出疑似重复，对每一对 `get` 双方；有把握的直接 `merge`（写 `reason`），拿不准的留着。
2. 分组用 `organize` 的 `add_to_group` / `move_to_group`；分组本身用 `groups` 管理。

## 按时间段整理（自动维护与回补）

档案是 Cindy 替用户写好的，用户主要是读。每次整理只处理一个时间段：

1. `maintenance` 传 `action: "begin"`，按需要带 `scope`：
   - `recent`（默认）：上次整理到现在；第一次是最近两周（用户可设 7 / 14 / 30 天）。
   - `backfill`：所有人往前补 `months` 个月。
   - `contact`：只补一个人（带 `contact_id`），只用这个人的身份和名字去查。
2. 先按 `first_step` 逐个确认来源能不能用（对应插件是否已安装、已连接；Cindy 对话的历史工具在插件发起的任务里可能不可用），用 `maintenance` 的 `action: "sources"` 报告每个来源的 `status` 和一句原因，页面会显示给用户。一个都不能用就直接 `end`，在 `note` 写清原因。
3. 按返回的 `segments`（新的在前）和可用的 `sources` 逐段、逐个来源查找。每个来源的 `how` 写了怎么按时间段查；没装、没授权的来源直接跳过，不要安装插件。
4. 与用户真实往来的每一条，用 `record` 记下：时间、来源、标题、一两句发生了什么（写清谁在等谁），必要时留一句原话；`ref` 填来源 id（邮件 message id、飞书消息 id、日程 id、PR URL），重复提交会自动跳过。找不到人时返回 `UNRESOLVED`：值得记的真人先 `save` 建档再记；营销、通知、机器人和用户自己发给自己的不记。
5. 有新往来的人：先 `get`，再用 `save` 更新：
   - `summary`：一句话是谁、在做什么。
   - `narrative`：两三段介绍，写这个人是谁、你们之间在做什么、最近的变化；保留仍然成立的旧内容。
   - `latest`：一句话最新动态（20 字以内），名单上显示在名字下面。
   - `facts`：要点，如 公司、常一起、怎么找 TA、记住。
   - `open_loops` / `close_loops`：还没完的事，谁在等谁、答应过的事；完结的关掉并写一句结果。
   同一时期的重要变化（入职、换岗、负责新事）用 `log_event` 记成履历。
6. 一轮改动不超过 `max_changes` 个人，先写来往最多的人，其余留到下一轮。
7. 最后 `maintenance` 传 `action: "end"` 和 `run_id`，带上读过的数量和新增、更新的人数。没有新内容也要 end，否则下一轮会重复这段时间。

档位：

- **同事为主**：每天一轮。重点是谁在等谁、职位与团队变化、新联系方式和约定。
- **客户很多**：每 6 小时一轮，上限更高。客户联系人挂到所属公司（`relate`，公司不存在时先建 `kind: "org"` 的档案），放进以公司命名的分组；往来里写清需求、报价、合同、跟进约定和下次联系时间。

导入大量联系人（客户名单、表格、名片）时用 `save_many`，每次最多 100 条，逐条处理返回的失败。
